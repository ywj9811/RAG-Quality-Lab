# ADR-0005: Spring AI VectorStore 대신 자체 `document_chunks` 테이블로 벡터 검색

- 상태: 제안됨 (2026-11-12)
- 관련: DOC-04, DOC-05, 명세 6·7절

## 배경
Spring AI `PgVectorStore` 기본 스키마는 `vector_store(id, content, metadata json, embedding)` 단일 테이블이다. 명세는 청크에 문서 FK·버전·위치·임베딩 모델 정보를 요구하고, 삭제 즉시 검색 제외와 과거 검색 스냅샷 보존(재현성)을 요구한다.

## 결정 (제안)
- Flyway로 `document_chunks`(`vector(1024)`, HNSW cosine) 생성.
- 검색은 `JdbcTemplate` 네이티브 SQL: `documents` 조인 + `status='READY' AND deleted_at IS NULL` 필터 + `ORDER BY embedding <=> :q LIMIT :k`.
- Spring AI는 `EmbeddingModel`(Ollama)과 `ChatModel`(Gemini)만 사용. `spring-ai-starter-vector-store-pgvector`는 추가하지 않음.

## 대안
- Spring AI PgVectorStore + metadata 필터: 코드 적음. 그러나 FK·제약조건 불가, json 메타데이터 필터 성능, 삭제 정합성(두 테이블 동기화) 문제.

## 결과
- 검색 SQL·매핑을 직접 작성·테스트(Testcontainers)해야 함.
- 스키마를 DB 마이그레이션으로 완전히 통제. 불필요한 `hstore`, `uuid-ossp` 확장 미사용.
