# ADR-0003: 임베딩 모델 Qwen3-Embedding-0.6B, 1024차원

- 상태: 제안됨 (2026-11-12)
- 관련: 명세 2.1, DOC-04, CLAUDE.md 3·8절

## 배경
- `qwen3-embedding:0.6b`: 639MB, 32K 컨텍스트, 최대 1024차원(MRL 32~1024), 100+ 언어, Apache-2.0.
- MTEB Multilingual 평균: 0.6B 64.33 / 4B 69.45 / 8B 70.58. 한국어 단독 점수는 공식 자료에 없음.
- pgvector `vector` 타입 HNSW 인덱스 한도 2000차원.
- 질의는 `Instruct: {task}\nQuery:{query}` 형식 권장(문서는 그대로) — 비대칭 임베딩.

## 결정 (제안)
- 기본 모델 `qwen3-embedding:0.6b`, **차원 1024 고정**(`vector(1024)`), 코사인 거리, 벡터 L2 정규화 확인.
- `EmbeddingPort`에 `embedDocument(text)`/`embedQuery(text)`를 분리하고, 질의에만 영어 instruction 접두어 적용
  (예: `Instruct: Given a Korean technical question about Java/Spring, retrieve relevant passages that answer it\nQuery:`). 접두어는 설정값.
- 청크마다 `embedding_model`, `embedding_dim` 저장. 모델 변경 시 전체 재인덱싱(혼합 검색 금지).

## Phase 1 확인 결과 (2026-11-12)
- Ollama 0.40.13 + Spring AI 2.0.2에서 1024차원 벡터 생성, L2 노름 1.0(정규화된 상태로 반환).

## 검증 계획
- Phase 2에서 골든셋 `ANSWER` 질문 32개로 Recall@5·MRR 측정. instruction 유/무 비교.
- Recall@5 < 0.8이면 `4b` 전환 제안(MRL로 1024 유지 → 스키마 변경 없음).

## 대안
- `4b`/`8b`: 품질↑, 용량 2.5/4.7GB, 속도↓. 8B 기본 4096차원은 HNSW 한도 초과(MRL 축소 필요).
- Gemini Embedding API(무료 티어): 데이터 외부 전송·한도 소모 → 비추천.
