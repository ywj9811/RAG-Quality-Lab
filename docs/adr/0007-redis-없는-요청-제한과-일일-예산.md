# ADR-0007: Redis 없이 요청 제한과 일일 호출 예산 구현

- 상태: 제안됨 (2026-11-12)
- 관련: CHAT-08, 명세 2절(fail closed), 2.3(Redis 미사용), RK-02

## 결정 (제안)
- **요청 제한:** 애플리케이션 메모리의 토큰 버킷(IP 해시별 분당 10회, 세션별 분당 5회; 설정값). 단일 인스턴스 MVP이므로 충분. 오래된 키는 주기적 정리로 메모리 상한 유지. 직접 구현(작은 클래스 + 단위 테스트), 새 의존성 없음.
- **일일 예산:** `llm_usage_records`를 태평양 시간 자정 기준(Gemini RPD 초기화 기준)으로 집계해 생성/평가 예산을 **분리** 관리. 호출 전 예약(행 삽입) 후 결과 갱신 방식으로 동시 요청에도 초과 방지. 초과 시 `503 DAILY_QUOTA_EXCEEDED`.
- 외부 429 수신 시 재시도 최대 1회(`Retry-After` 존중), 이후 실패 처리. 유료 폴백 없음.

## 대안
- Bucket4j(인메모리): 검증된 라이브러리지만 MVP 규모에서는 의존성 추가 대비 이점 작음.
- Redis: MVP 범위 밖(오너 결정).

## 결과
- 재시작 시 분당 제한 카운터는 초기화되나, 일일 예산은 DB 기반이라 유지됨.
- 다중 인스턴스로 확장 시 재설계 필요(문서화).
